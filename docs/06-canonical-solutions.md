# Solutions canónicas de DEO

**Vigencia:** permanente como frontera conceptual.

**Estado de esta etapa:** no hay una solution activa ni infraestructura de solutions que deba conservarse. `contact_dossier`, sus applications, relaciones y superficie de Expediente se retiran sin sustitución.

## Propósito

Una solution es una composición futura de varias piezas —capabilities, relaciones, acciones, vistas o flujos— para una intención de producto reconocible. No es una capability grande, no crea una entidad base adicional y no determina la identidad de una lista.

Una futura solution deberá declarar compatibilidad, requisitos, lifecycle, recursos tipados y efectos de activación/desactivación antes de ofrecerse. Su implementación no puede persistir código, callbacks o SQL arbitrario ni contaminar el shell.

## Fuera de alcance actual

No se construyen registry, tabla común, applications, relaciones, UI, presets, importación/exportación, runtime público ni motor universal de workflows/relations. El texto e implementación históricos de `contact_dossier` se conservan solo como antecedente; no son autoridad operativa.
